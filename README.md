# kiota-dart-error-copywith-repro

Minimal synthetic reproduction: a discriminated error type generated by Kiota for Dart loses its concrete subtype
(and its subtype-only fields) between deserialization and the exception the caller catches.

- Schema: `openapi.yaml` (base `ProblemDetailsDto` with a `type` discriminator; `ConflictProblemDto` adds `conflictId`).
- `bin/observe.dart` sends responses through the real `HttpClientRequestAdapter` (only the HTTP transport is a `MockClient`)
  and prints what the caller catches.
- `scripts/reproduce.sh <kiota-version> [pinned|latest]` generates the client, requires `dart analyze` to report no errors,
  runs `bin/observe.dart` and diffs against `expected/observed.txt`.
  Exit 0 = erasure reproduced, 1 = output changed (e.g. fixed upstream), 2 = setup failure.

Fresh clone:

```sh
git clone https://github.com/ricardoboss/kiota-dart-error-copywith-repro && cd kiota-dart-error-copywith-repro
scripts/reproduce.sh 1.36.1 pinned   # microsoft_kiota_abstractions 0.3.0, microsoft_kiota_http 0.0.7
scripts/reproduce.sh 1.36.1 latest   # newest runtime packages allowed by pub (abstractions 0.3.1 at time of writing)
```

Needs the .NET 8 SDK and Dart 3.x. Expected output (both modes): `direct-parse` returns `ConflictProblemDto`,
but the exception thrown by the adapter for the 409 is a plain `ProblemDetailsDto` (`conflictId` unreachable),
while `statusCode`, headers and `additionalData` are present. CI runs both modes.

See `UPSTREAM_REPORT.md` for copy-ready text. Nothing has been posted upstream.
